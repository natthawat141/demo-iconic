# Client Demo Runbook — Nong Fah / ICONIC

ใช้เอกสารนี้สำหรับเดโม 10–12 นาที จุดประสงค์คือให้ลูกค้าเห็นวงจรงานจริง: **ถามงาน → ใช้ความรู้ที่อนุมัติแล้วหรือข้อมูลที่แนบ → เห็นหลักฐาน → ส่งเรื่องที่ระบบยังไม่รู้ให้คนรับผิดชอบ** ไม่ใช่สัญญาว่า AI ตอบได้ทุกเรื่องโดยไม่ต้องตรวจสอบ

Public demo: <https://iconic-knowledge-assistant-50194055876.asia-southeast1.run.app>

## ก่อนเริ่ม 5 นาที

1. ใช้บัญชี Member สำหรับมุมผู้ใช้งาน และเปิดแท็บ Admin แยกไว้ล่วงหน้า
2. เริ่มบทสนทนาใหม่ เพื่อให้ประวัติและผลลัพธ์ที่โชว์อ่านง่าย
3. เปิด `/library` และดาวน์โหลด `Operations workbook` ไว้บนเครื่องล่วงหน้า
4. ห้ามใช้ข้อมูลส่วนบุคคล, ข้อมูลลูกค้า, ข้อมูลการเงินจริง หรือไฟล์ที่เป็นความลับในเดโมนี้
5. อย่ากด reset ระหว่างประชุม เพราะอาจกระทบประวัติ/ไฟล์เดโมของผู้ใช้อื่น ใช้เฉพาะข้อมูลตัวอย่างที่เตรียมไว้

## ลำดับเดโมหลัก

| เวลา | สิ่งที่ทำ / prompt ที่วางได้ | สิ่งที่ลูกค้าควรเห็น | คุณค่าที่สื่อ |
| --- | --- | --- | --- |
| 0:00–0:45 | เปิดหน้าแชทใหม่ แล้วถาม `API คืออะไร?` | คำตอบปกติ อ่านง่าย ไม่มี Source card ของบริษัท | AI คุยเรื่องทั่วไปได้ลื่น ไม่ค้นเอกสารภายในโดยไม่จำเป็น |
| 0:45–2:00 | `ค่าแท็กซี่ไปพบลูกค้าเบิกได้ไหม และต้องแนบอะไร?` | คำตอบจาก Approved Knowledge พร้อมแหล่งอ้างอิง | ลดเวลาหาคู่มือ และให้ผู้ใช้ย้อนกลับไปตรวจต้นทางได้ |
| 2:00–3:00 | `วันแรกของพนักงานใหม่ต้องเตรียมอะไรบ้าง?` | คำตอบที่อ้างอิงขั้นตอน Onboarding ของบริษัท | นำความรู้กระจัดกระจายมาเป็นคำตอบที่ใช้ทำงานได้ทันที |
| 3:00–5:00 | แนบ `Operations workbook` จาก Library แล้วถาม `สรุปแนวโน้มค่าใช้จ่ายจากไฟล์นี้ และสร้างกราฟที่ช่วยดูรายการสำคัญ` | ชื่อชีต, สรุปคอลัมน์/ตัวอย่างข้อมูล และกราฟจากตัวเลขจริงในไฟล์ | ลดงานอ่าน Excel และเริ่มบทสนทนาจากข้อมูลเดียวกันทั้งทีม |
| 5:00–6:00 | `ทีมมี template เอกสารภาษาอังกฤษที่อนุมัติแล้วหรือยัง?` | ระบบไม่แต่งคำตอบขึ้นเอง, บอกว่า Knowledge ยังไม่พอ และสร้าง/เสนอส่งต่อ Knowledge Gap | ทำให้เห็นว่าเมื่อไม่รู้ ระบบสร้างงานให้ทีม ไม่หลอกว่ารู้ |
| 6:00–8:00 | สลับไป Admin: เปิด Users/Conversations และ Knowledge Gaps | เห็นผู้ใช้, ประวัติคำถาม, แหล่งอ้างอิง/ไฟล์ และ Gap ที่เกิดจากข้อก่อนหน้า | เจ้าของระบบมองเห็นการใช้งานจริงและจัดลำดับสิ่งที่ควรเติมความรู้ได้ |
| 8:00–9:30 | เปิด Admin AI แล้วถาม `มี Knowledge Gap อะไรที่ควรเปลี่ยนเป็น Draft?` | ข้อเสนอแนะสำหรับงาน review; การอนุมัติยังอยู่กับแอดมิน | ช่วยผู้ดูแลจัดงาน ไม่อนุมัติหรือเปลี่ยนความรู้เอง |
| 9:30–12:00 | ให้ลูกค้าลองเลือก prompt หนึ่งชุดด้านล่าง หรือพิมพ์คำถามจากงานจริงที่ตัดข้อมูลลับออกแล้ว | หากตรง Knowledge จะได้ Source; หากไม่ตรง จะเป็น Gap ที่มี owner ตรวจต่อ | เปลี่ยนจาก "เดโมสำเร็จรูป" เป็นการเห็นว่าใช้กับทีมลูกค้าอย่างไร |

## Prompt cards ตามงาน

ให้เริ่มด้วยบัตรที่ใกล้บทบาทของลูกค้าที่สุด ไม่ต้องรันทุกใบในหนึ่งรอบ

### ฝ่ายขาย / ดูแลลูกค้า

```text
ลูกค้าไม่ตอบหลังส่งแผน ควรติดตามอย่างไรโดยไม่กดดัน?
```

```text
ลูกค้าขอปรึกษาคู่สมรสก่อน เราควรปิดการสนทนาและนัดติดตามอย่างไร?
```

สิ่งที่สื่อ: ทีมใช้ playbook เดียวกัน แต่คำตอบยังมี Source ให้คนตรวจได้

### การเงิน / จัดซื้อ

```text
ขั้นตอนยื่นเบิกค่าใช้จ่ายมีอะไรบ้าง และอะไรทำให้คำขอถูกส่งกลับ?
```

```text
ถ้าต้องการซื้อบริการใหม่ให้ทีม ต้องเตรียมข้อมูลอะไรเพื่อขออนุมัติ?
```

สิ่งที่สื่อ: ลดคำถามซ้ำและทำให้คำขอมีหลักฐานครบก่อนส่งต่อ Finance

### HR / Onboarding

```text
ผู้จัดการต้องเตรียมอะไรให้พนักงานใหม่ในวันแรก?
```

```text
ถ้าจะขอสิทธิ์เข้าถึงโฟลเดอร์โครงการ ต้องระบุข้อมูลอะไรบ้าง?
```

สิ่งที่สื่อ: คนใหม่เริ่มงานได้เร็วขึ้น และสิทธิ์ไม่ถูกให้กว้างเกินจำเป็น

### ข้อมูล / ผู้จัดการทีม

แนบ `Operations workbook` แล้วเลือกหนึ่งคำถาม:

```text
สรุปชีต Sales pipeline ให้หน่อยว่า ทีมและช่องทางไหนมีมูลค่าโอกาสสูง พร้อมสร้างกราฟ
```

```text
ดูชีต Onboarding แล้วบอกว่าทีมไหนควรได้รับการติดตามเพิ่ม พร้อมเหตุผลจากตัวเลขในไฟล์
```

```text
จากชีต ค่าใช้จ่าย ช่วยสรุปแนวโน้มยอดเบิกจ่ายเทียบงบประมาณ และสร้างกราฟเส้น
```

สิ่งที่สื่อ: ไม่ใช่แค่เก็บไฟล์ แต่ช่วยสรุปตัวเลขและสร้างจุดเริ่มต้นให้การประชุม

## คำถามเสริมที่ใช้เมื่อ Tavily พร้อม

ใช้เพื่อแสดงการค้นหาข้อมูลสาธารณะเท่านั้น และให้ผู้ชมเห็นว่าเป็นข้อมูลจากเว็บ ไม่ใช่กฎภายในบริษัท

```text
ค้นหาข่าวล่าสุดเกี่ยวกับ AI สำหรับธุรกิจในประเทศไทย แล้วสรุป 3 ประเด็นพร้อมแหล่งอ้างอิง
```

หาก Tavily ไม่พร้อมหรือ quota หมด ให้ข้ามช่วงนี้ทันที ไม่ควรให้การค้นเว็บเป็นแกนหลักของเดโม

## ประโยคที่ผู้สาธิตควรพูด

- "คำตอบเรื่องภายในจะอ้างเฉพาะ Knowledge ที่ทีมอนุมัติแล้ว และเปิดแหล่งที่มาให้ตรวจได้"
- "ถ้ายังไม่มีความรู้ ระบบไม่เดา แต่เก็บคำถามนั้นเป็นงานให้เจ้าของความรู้ตอบและอนุมัติ"
- "ไฟล์ยังอยู่แบบ private; หน้า Admin เห็น metadata และประวัติที่จำเป็นต่อการบริหารเดโม"
- "ผลจากไฟล์เป็นจุดเริ่มต้นในการวิเคราะห์ ไม่ใช่การตัดสินใจอัตโนมัติแทนคน"

## สิ่งที่ไม่ควรสัญญาในเดโม

- ไม่สัญญาว่าคำตอบทั่วไปหรือเว็บเป็นคำแนะนำเฉพาะบุคคล
- ไม่สัญญาว่า AI อนุมัติ Knowledge, ค่าใช้จ่าย, การซื้อ หรือสิทธิ์เข้าถึงแทนผู้มีอำนาจ
- ไม่อัปโหลดไฟล์จริงของลูกค้าเพื่อ "ลองให้ดู" โดยยังไม่ตกลงเรื่องข้อมูลและสิทธิ์

## เกณฑ์จบเดโมที่ดี

ถือว่าเดโมประสบความสำเร็จเมื่อผู้เข้าชมเห็นอย่างน้อย 4 เรื่องนี้ด้วยตนเอง:

1. คำตอบทั่วไปลื่นไหล โดยไม่แกล้งอ้างว่าเป็นข้อมูลบริษัท
2. คำถามภายในได้คำตอบพร้อม Source ที่ตรวจย้อนกลับได้
3. คำถามที่ไม่มีข้อมูลไม่ถูกแต่งขึ้น และกลายเป็น Gap ที่คนทำงานต่อได้
4. Excel ตัวอย่างให้สรุปและกราฟจากข้อมูลจริง พร้อม Admin เห็นภาพรวมการใช้งาน
